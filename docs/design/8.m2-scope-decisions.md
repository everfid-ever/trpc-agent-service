# M2 范围决策记录

本文记录 M2 验收中必须显式冻结的范围调整。它只改变阶段交付范围，不修改 Channel、Tenant、Secret 或 Delivery Ledger 的安全契约。

## M2-SD-001：WeCom 智能机器人 Bot transport 与群聊 mention 延后

| 属性 | 决策 |
|---|---|
| 状态 | accepted for M2 scope |
| 决策 owner | trpc-agent-service maintainers / M2 release owner |
| 记录日期 | 2026-09-04 |
| 复查日期 | 2026-09-09，进入 P3/M3 生产化集成前 |
| M2 保留范围 | WeCom Agent 加密 XML callback、URL challenge、p2p 文本/基础媒体、应用消息发送、token refresh、Reply Queue/Delivery Ledger/reclaim |
| M2 移出范围 | WeCom 智能机器人 WebSocket/Webhook transport、`aibot_msg_callback`、群聊 `chatid/chattype` 与 Bot mention、流式 `aibot_respond_msg` |

### 原因

WeCom 智能机器人不是现有 Agent XML callback 的字段扩展，而是独立的长连接/JSON 协议和连接所有权：需要 BotID/Secret 订阅认证、心跳与重连、`req_id` 回复队列、短时 `response_url`、连接 generation、流式 finish/ambiguous 对账以及群聊身份规则。当前固定依赖中没有获批的官方 Go SDK；把非官方 transport 或简化 JSON parser 直接接到生产入口，会绕过现有 candidate verifier、durable ACK、Secret scope 和 Delivery Ledger 状态机。

M2 的核心目标是完成分布式 Runtime 与 Feishu/WeCom 最小可靠链路。WeCom Agent 已提供经过真实官方 HTTP API 形态验证的 p2p 入口与发送能力，因此 Bot transport 不作为 M2 发布阻断项；未知 Bot/WebSocket 帧继续 fail closed，不能回退到 Agent parser。

### 影响

- M2 不支持把智能机器人加入 WeCom 群聊后通过 `@机器人` 触发 Agent，也不支持 Bot 流式回复。
- Feishu 群聊严格 mention 保持支持，不受该决策影响。
- WeCom Agent p2p、媒体预处理和应用消息发送保持在 M2 验收范围。
- 产品说明、部署清单和演示不得宣称 WeCom Bot/群聊能力已实现。

### 替代验收

1. WeCom Agent callback 的签名、AES、CorpID/AgentID、时钟窗、重复入站和 URL challenge contract 全部通过。
2. WeCom Agent OfficialSender 的 token refresh、provider 错误分类、Delivery Ledger 幂等、Redis Reply Queue consume/reclaim 通过。
3. `scripts/m2_im_provider_smoke_test.sh` 使用真实 WeCom Agent credential 向授权测试用户发送随机 nonce，并与真实 Feishu Reply smoke 同轮执行。
4. 非 `text/image/file` Agent 消息、缺失 AgentID 或任何 Bot JSON/WebSocket 数据输入 Agent HTTP endpoint 时必须 fail closed。

### 后续恢复条件

P3/M3 只有在以下条件同时满足后才重新纳入 Bot：选择并固定经评审的官方 transport/SDK；定义 Bot binding 与 `channel_send/channel_verify` Secret schema；冻结 WebSocket connection generation 和 `req_id`/response URL 持久状态；补单聊/群聊 mention、断线重连、ACK 前崩溃、finish ambiguous 与真实企业 Bot smoke。未满足时保持 blocked，不用 Agent API 模拟 Bot。
